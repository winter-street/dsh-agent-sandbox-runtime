## Verified behavior

1. Real AgentLoop/tool registry executes `runtime_probe_add` once, returns `{ sum: 5 }`, and persists a tool-result event.
2. `agent/request` changes the cap from 400 to 128; every actual local-adapter request sees the frozen 128 cap, and the request header records it.
3. A child has its own request session ID and persists its parent-session lineage.
4. Throw-before-usage and partial-stream disconnect both finish as errors with usage unknown.
5. Agent cancellation reaches the adapter signal, yields an aborted finish and leaves usage unknown.
6. JSONL flush, dispose and same-session resume preserve existing message identities; new work appends successfully.
7. Tool registration disposal removes the tool.
8. Agent handles and all root-owned effects clean up without an error.

The report groups items 1 and 2 as one assertion and the two error modes as separate assertions. Full sanitized event order: `spikes/harness-hooks/result.json`.

## Limits

No credential or external model was used, so there was no paid provider consumption. The local adapter's usage counters are synthetic. Root budget resolution/accounting was not exercised because the budget plugin is not installed by this probe. This proves conversation-log resume, not process-crash recovery, sandbox checkpoint recovery, or Loader/profile launch. Those remain separate integration work and must not be reported as passed based on these eight checks.
