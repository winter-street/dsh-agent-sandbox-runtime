# P1-05：步骤调度与执行提交

状态为核心执行闭环及真实沙箱集成已验收，完整 Harness、预算与真实模型演示由 P1-08 补齐。2026-11-19 的 G1 逐项验收见 QA-02。实现位于当前工作树，仓库基线见 P0-01。

`src/core/service.ts` 在执行前创建 attempt、持久化 DISPATCHING 意图，再调用远端沙箱。收集后先通过 ArtifactStore 发布和校验文件，再在 SQLite 事务内提交产物引用、attempt/step 状态和 tool.finished，随后保存 checkpoint。相同 run 的在途调度拒绝重入；相同 step 已完成时回放原结果，不重新启动脚本。完整完成还需要独立验证器和全部必需步骤通过。

验证命令：

```powershell
pnpm exec vitest run tests/core/service.test.ts tests/storage/store.test.ts
$env:OPEN_SANDBOX_API_KEY = (Get-Content -Raw .runtime/sandbox-smoke/api-key.txt).Trim()
try { .\spikes\sandbox-smoke\run-runtime-service-docker.ps1 }
finally { Remove-Item Env:OPEN_SANDBOX_API_KEY -ErrorAction SilentlyContinue }
```

此 smoke 的预算是显式 FakeBudget；没有模型调用、付费 provider 或真实预算插件组合。该默认场景通过异常注入和关闭/重开存储模拟恢复。之后单独增加的 `-Scenario process-recovery` 已完成实际 SIGKILL worker 后重连同一远端、补交同一 attempt，见 P2-06；预算仍是 FakeBudget。另有真实 Harness/原预算插件/沙箱与受控 provider 的组合证据见 P1-06-harness；没有外部模型推理。均不代表任意副作用 exactly-once 或所有崩溃点已验证。真实部署版本和复跑前提见 docs/environment.md。
