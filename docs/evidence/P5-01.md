## State and scheduling contract

Graph specification version 1 rejects duplicate nodes/dependencies, missing references, cycles and a condition referencing anything other than a direct dependency. A required node cannot be conditional or depend on optional work. Conditions compare a finite JSON primitive against an own-property path in a **completed** dependency result. False conditions and failed optional dependencies skip optional nodes; a required failure stops the active graph. Optional failure can still permit completion if all required work passed; UNKNOWN, pending, running or cancellation prevents full completion.

Persisted graph state version 2 has a strict schema, exact node membership, graph hash, trusted host/root binding hash, monotonic revision, graph owner token and per-dispatch claim ID. Root binding includes input hash, session, original budget scope/deadline/policy and runtime identity. Done states require validated finite JSON data and an artifact manifest; required nodes cannot be silently skipped. Historical version 1 or corrupt state is rejected rather than reset. A SQLite transaction claims ownership before any asynchronous admission or dispatch callback; distinct workflow objects cannot dispatch the same graph.

Running and UNKNOWN states cannot be reset to pending for an automatic retry. Trusted host reconciliation must provide an exact revision, evidence and an outcome for every unresolved node. For asynchronous recovery, `claimReconciliation` persists an exclusive owner **before** remote inspect/collect, resume, validation or cancellation; `commitReconciliation` checks that owner and revision. A failed recovery releases its active claim while retaining unresolved state. The synchronous reconciliation convenience method wraps claim/outcome validation/commit in one transaction. Empty evidence is rejected before side effects.

The existing RuntimeStore process writer lock supplies the cross-process single-writer boundary; this graph code is not a distributed multi-writer lease system. Within the writer process, active graph/recovery owners block another facade. If a bounded cancellation leaves the original execute/cancel promise outstanding, UNKNOWN retains ownership and local recovery remains blocked until those callbacks settle. A process restart may inspect its persisted remote execution identity; it still cannot blindly redispatch.

## Dependency and artifact evidence

Each branch manifest has its own `branches/<nodeId>/` virtual namespace. Validation rejects traversal, unsafe Windows names, alternate streams, invalid/non-normalized paths, case collisions, file/directory collisions, invalid hashes/sizes and oversized/nonfinite result data. Completed dependency results are copied before being supplied to the next callback. All retained artifacts are reverified during the final merge and replay. A bad prior artifact invalidates the completed evidence of that node and its completed descendants; it is never silently reexecuted.

The concrete RuntimeBranchWorkflow verifies dependency source records/content and copies their actual bytes into the dependent child's `dependencies/<nodeId>/...` input files. Fixed host code, input hashes, expected artifacts and validator versions are bound to the graph. Its dependency/validation receipt includes the dependency result hash. This composition uses actual RuntimeService/SQLite/artifact publication and an independent host validator; its local tests explicitly use fake sandbox, budget and time ports.
