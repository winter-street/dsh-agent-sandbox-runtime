## Facilities and activation

- `FakeClock` provides bound `now`/`sleep` callbacks and monotonically advances logical time immediately. It rejects backwards time, negative durations, and unsafe integer overflow. Logical sleep is not elapsed wall time or a simulation of CPU scheduling.
- `FakeFaults` queues one-shot synchronous callbacks by explicit point name, records hits, and reports unused callbacks. With no registered callback a point is a no-op. Faults must be explicitly registered by tests; these helpers do not run containers, interpret code, or contact a model/provider.
- `FakeSandbox` queues running/terminal/unknown execution status, logs calls, returns copied results, rejects forged execution identities, supports cancellation that remains unconfirmed, and preserves an accepted execution after the caller loses the start response. `executionRefs` and `setStatus` are test-only observation/control, not remote recovery API guarantees.
- `FakeBudget` is one in-memory root ledger with synchronous atomic admission, global/work/finalize allocations, concurrency slots, reservation/dispatch/unknown/settlement events, stable replay, duplicate detection, disjoint normalized usage, and asynchronous session-scoped trusted purpose context.
- `runtimeFixture` assembles real local SQLite/artifact stores with these fake ports; service tests use an equivalent fixture with optional runtime fault callback. This is test setup rather than a production scenario CLI.
- Model-policy tests have a controlled `LlmAdapter` that yields deterministic text, usage, and finish events and can wait on a test gate. This is a test-local provider fixture; there is no shared configurable fake external provider or network service in `tests/support`.

## Contract correction from this review

The old fake permanently rejected any repeated `(runId, attemptId)` at the remote port. The real `OpenSandboxAdapter` does not provide server-side idempotency by attempt ID: after a confirmed terminal execution, the same request can execute again. That fake behavior could hide a runtime replay bug.

The fake now permits such a repeat and returns a new execution ID. Durable replay prevention remains the responsibility of `RuntimeStore` and `RuntimeService`. The fake also uses a fence per sandbox, matching the adapter, rather than imposing an extra cross-sandbox run restriction. The runtime's separate per-run scheduling constraint remains its responsibility. A start response failure keeps a conservative uncertainty fence; out-of-band test observation does not silently clear it.

Three sandbox regression cases verify these boundaries. Two additional budget regression cases distinguish failure before versus after dispatch persistence and failure before settlement persistence.

## Limits

No external model request, Docker container, or real OpenSandbox execution was part of these checks. Fakes are process memory; recreating a client over the same fake or JSON-roundtripping a reference is not server/process restart evidence. Runtime recovery tests replace a service over the same fake remote state; SQLite close/reopen and writer-process tests are real local persistence checks with narrower scope. The fake's before/after mutation hooks model commit boundaries, not disk-full, torn-write, fsync, network partitions, or database corruption. None of these tests promises exactly-once external execution.

Production-provider accounting, complete real-service cancellation/recovery, broad crash-window coverage, and G1–G5 acceptance remain covered by their own task gates. This evidence records the QA facility and observed tests without accepting those gates.
