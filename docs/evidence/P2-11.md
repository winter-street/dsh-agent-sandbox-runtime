Policy state contains schema/policy version, rules fingerprint (including observe/enforce mode), stage, latched finalization, notified stages, last transition counters, monotonic step/settlement counters and evaluation count. Runtime commits state and decision/notification events in one SQLite transaction. No second balance is persisted by policy.

The pure suite checks exact threshold boundaries, reservation pressure distinct from settled usage, waiting for outstanding settlement rather than latching finalize, hysteresis plus settlement/two-step cooldown before returning capacity, notification deduplication after serialization/re-entry, latched finalize until a trusted explicit release, rejected mode/version/config changes and backwards counters. Required cleanup remains possible under unknown/cancel/deadline where permissions allow it.

Two component-integration scenarios independently exercise enforce and observe. At 70% seeded usage they run a real Cordis/DSH request and one original-plugin automatic controlled model call, store the policy decision in real SQLite, then close and recreate **both Cordis/plugin and SQLite within the same process**. The original budget snapshot and policy state are byte-equivalent after reopening; the next request retains its intended cap (750 enforce / 1000 observe), and `policy.triggered` remains a single persisted event. This is stronger than only JSON roundtripping state, and is not an actual operating-system process termination test.

The unknown scenario similarly reopens the original ledger and SQLite, retains the paused run, original scope, receipt cursor and committed artifact, rejects resume while usage is unknown, and resumes only after explicit trusted fixture reconciliation. The restored original ledger is not replaced or credited again. Monotonic counter and config incompatibility are checked by the engine; full runtime checkpoint identity/real crash windows are outside this scenario's claimed coverage.

Validation commands/totals are in [P2-12](P2-12.md). Remaining acceptance: true process-kill/profile recovery and the complete end-to-end task/phase gate. No external provider or billing guarantee is inferred from the controlled fixtures.
