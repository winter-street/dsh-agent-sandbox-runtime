# P1-03: OpenSandbox adapter implementation

Status updated 2026-11-19. **Adapter lifecycle acceptance and the original G1 requirements passed.** Bounded deployment isolation is recorded in P0-04-isolation. RuntimeService integration and its recovery reports are mapped in QA-02.

Date: 2026-11-16 (Asia/Shanghai).

## Delivered

- `src/adapters/opensandbox/index.ts`: implements the shared SandboxPort using the published OpenSandbox SDK. Supports create, background execute, reconnect, inspect, confirmed cancellation, bounded collection, confirmed lifecycle deletion and repeat cleanup.
- `src/adapters/opensandbox/scripts.ts`: fixed Python runner and collector executed only inside the remote sandbox. User code is uploaded as a file; the command is an argv array. No local execution fallback exists.
- `tests/adapters/opensandbox.test.ts`: typed SDK-client contract tests, explicitly labelled mock-client tests.

The runner starts its child inside execd's command process group so timeout and interrupt can reach both. It captures stdout/stderr separately with bounded files and uses Linux pidfd support to clean same-group descendants after normal exit. This requires Python >=3.9 and Linux pidfd support. Deliberately escaped sessions are not claimed to be controlled by this runner; sandbox destruction remains the final resource boundary.

The collector opens directory components and files with O_NOFOLLOW, refuses non-regular output files, limits recursion/file count/total bytes, and returns a typed manifest plus bytes. The host rechecks paths, base64 encoding, uniqueness and byte counts before passing results to ArtifactStore. These scripts are not a substitute for real deployment confinement tests.
