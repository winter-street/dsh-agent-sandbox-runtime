# P0-04: OpenSandbox environment verification

Status: **accepted for the bounded environment probe**. Real OpenSandbox SDK create, file transfer, command execution, cancellation, timeout, and deletion passed against a Docker-backed 1.2.1 deployment. Project-adapter integration and reconnection passed separately (P1-03); RuntimeService artifact publication, reopen/reconciliation and active cancellation passed later (P1-05/P1-07). On 2026-11-17 the separate [deployment probe](P0-04-isolation.md) exposed a direct-IP bypass in dns mode; switching only local egress mode to dns+nft and recreating the server made all eight bounded network/permissions/mount/CPU/memory checks pass. This does not accept G1 or complete tenant isolation.

## Reproduction

From the repository root, load the ignored local key into the current PowerShell process and run:

```powershell
$env:OPEN_SANDBOX_API_KEY = (Get-Content -Raw .runtime/sandbox-smoke/api-key.txt).Trim()
.\spikes\sandbox-smoke\run-docker-client.ps1
Remove-Item Env:OPEN_SANDBOX_API_KEY
```

The tested helper exits 0 and writes the full key-free report to `.runtime/sandbox-smoke/smoke.json`. The helper runs the SDK client in Docker on the Compose network; it does not use host shell execution as a fallback.

## Findings

- The first server-container config used `host_ip = "127.0.0.1"`. OpenSandbox's egress readiness probe then looked for the host-published sidecar port at the server container's loopback and received connection refused. Setting `host_ip = "host.docker.internal"`, matching the official Compose example, allowed the sidecar to become ready.
- The initial 1.1.0 service/executor configuration did not accept the 1.2.1 SDK's `argv` request in this profile. Pinning server, execd, and egress to the 1.2.1 release digests resolved the request validation failure.
- A deny-default policy request alone is configuration evidence. The original generic smoke did not test outbound DNS/direct IP, mounts, file permissions or CPU/memory pressure; the separate P0-04-isolation probe now records those real results, the initial failure and the authorized remediation. Root control processes, writable root layers, published endpoint exposure and broader tenant isolation limits remain documented there.
- This smoke calls the published SDK directly. Repository `OpenSandboxAdapter` real-service evidence is recorded separately in [P1-03](P1-03.md); neither smoke proves RuntimeService artifact publication or restart recovery end to end.
