## Implemented

- Tool metadata declares input/output schemas, host/sandbox/MCP-host location, permissions, timeout, retry codes, idempotency, and maximum output bytes.
- Inputs must be canonical lossless JSON and pass Ajv validation before the executor is called. Permissions, cancellation, optional policy admission, output schema, and output size are checked at the registry boundary.
- Results use stable `(runId, callId)` identities and distinguish invalid input, permission denial, local policy rejection, timeout, cancellation, unknown execution, tool failure, invalid output, and oversized output.
- Durable claims make repeated identical calls return the stored result, conflicting reuse fail, and pending claims return `EXECUTION_UNKNOWN` rather than dispatch a second time. Failure feedback keys are stable per call and error category.

## Timeout retry correction

Timeout results never advertise automatic retry for a non-idempotent tool, including an executor that observes the abort signal but resolves normally. A regression test covers that alternate completion path.
