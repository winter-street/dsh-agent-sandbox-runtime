# P1-04: Artifact storage implementation and verification

Status: **implemented and verified against real Windows filesystem**. No remote sandbox execution is claimed by these tests. Date: 2026-11-16 (Asia/Shanghai).

## Delivered interface

`src/artifacts/index.ts` exports `ArtifactStore(rootDir, { maxFiles?, maxBytes?, beforePublish? })`:

- `publish(runId, attemptId, outputs)` validates paths and limits, snapshots bytes, writes exclusive files plus manifest, fsyncs files and atomically renames an attempt directory.
- `verify(records)` and `read(record)` check authoritative manifest identity, regular-file status, size and SHA-256 before returning bytes.
- `list()` returns valid published attempts, staging directory names and invalid publications.
- `reconcile(referencedRecords)` additionally reports unreferenced artifacts without deleting anything or adding database references.

Publication layout: `<root>/runs/<runId>/attempts/<attemptId>/manifest.json` and `files/<artifact-relative-path>`. Temporary directories live below `<root>/.staging/` and are retained for explicit recovery decisions.

The same attempt with identical content returns existing artifact IDs; different content conflicts. No failed/retried attempt overwrites a successful attempt directory. ArtifactStore does not own the SQLite reference transaction; RuntimeService must save the returned records with its step/event transaction.

An early test failed because Node `rm` with `recursive:false` does not remove an empty directory on Windows. The test now uses `rmdir` for that exact empty directory; subsequent full reruns passed. No product path restriction was relaxed to satisfy the test.

## Limits and invariants

- File contents are fsynced. Directory fsync is also attempted on POSIX. Windows does not expose equivalent directory fsync through this API; tests establish process-interruption behavior, not a claim of guaranteed power-loss durability.
- Application-owned store directories must not be writable by unrelated local users. Existing symlinks/junctions are rejected and file identity is checked on read; these checks are not a replacement for OS filesystem access controls against a malicious concurrent host process.
- Only ArtifactStore-created directories are candidates for recovery inspection. No automatic orphan deletion is implemented.
- Test cleanup verifies the resolved temporary directory remains an `agent-artifacts-*` directory directly below the OS temp directory before recursive removal.

Implementation commit is to be recorded by the coordinating agent when committing the shared project changes.
