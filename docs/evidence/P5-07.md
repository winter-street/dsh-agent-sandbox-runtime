## Operating entries and retained data

Install and build the pinned budget dependency using [the budget setup](../../integrations/budget/README.md), then run `pnpm install --frozen-lockfile`. Configure the two service keys through `.env.local` using `.env.example`. The real demonstration runner loads these values and its `-CheckOnly` mode reports missing keys or config paths with a corrective action. Deployment prerequisites are listed in [the environment guide](../environment.md).

For a real file-backed example, run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run-demo.ps1`. The result directory retains runtime state, trace, ledger and exported delivery. For the HTTP application, load service keys into the process, set `ASR_RUNTIME_API_TOKEN` to a bearer token of at least 24 characters and run `pnpm app -- --config config/app.serial.example.json`. The CLI starts the API and client on loopback port 8787. The host `submit({ task, inputs })` entry supports attached files used by the example runner.

Stop the CLI with Ctrl+C. SIGINT/SIGTERM handlers close the HTTP server and call `host.close()`. Plugin disposal withdraws the tool and cancels active execution. Unfinished or unconfirmed work remains in the configured data directory for recovery. OpenSandbox is a separate local service managed through the deployment in the environment guide.

Run data is rooted at the application config's `dataDir`, resolved relative to that config file unless the host supplies `dataDirectory`. Preserve the complete directory for resumption, including `database/`, `artifacts/`, `sessions/` and `budget/`. To discard an old run, cancel or reconcile active work and confirm sandbox cleanup, stop the host, then remove the selected old data directory with PowerShell `Remove-Item -LiteralPath <resolved-data-directory> -Recurse`. Ignored `.runtime/` directories also contain evidence exports that can be archived or removed individually after they are no longer needed. Source reproduction creates a new directory and excludes those data and credential files.

## Historical host implementation and verification — 2026-11-17/18

The original host checks and real demonstration are retained below. Later reproduction, unload and recovery reports are included in the current assessment above.

The host in `src/app/index.ts` is the single composition root for Cordis/Harness, the original patched budget ledger, `RuntimeService`, `ArtifactStore`, `OpenSandboxAdapter`, and the DeepSeek adapter. It validates configuration and credential references before opening the durable store, keeps the root session's budget scope fixed, and exposes submit/wait/get/reconcile/close operations to the evaluator.

Startup scans existing non-terminal runs and calls `recover` plus receipt synchronization. Recovery only queries existing execution identities; it does not create a new run, reset allocation, or resend a model request. Shutdown aborts local agent work, waits a bounded interval, disposes the Harness context, and closes SQLite.

The acceptance boundary is intentionally explicit: injected providers/sandboxes are available only to controlled tests and are marked in `host.mode`; real evaluation requires the DeepSeek provider and OpenSandbox adapter. The early controlled checks below do not establish external-model behavior; the later real demonstration is identified separately.

The CLI can load `validatorModule` from the application configuration. The charging-analysis validator receives only committed artifact records and a read callback, performs structural checks, and does not expose budget or permission controls. Its semantic answer check remains the independent `verify.py` path.
