### Event and cursor behavior

The API reads committed SQLite events in ascending per-run `eventSeq` order after `Last-Event-ID`. A snapshot's `lastEventSeq` can be used as the subscription cursor, including when new events arrive between the snapshot and connection. Sequence IDs are durable, so observers can resume independently of execution. Disconnecting an observer does not cancel its run.

Each flush reads at most 64 rows through a SQL-limited query and sends one page per polling tick; determining the durable tail uses `latestEventSeq`, without loading history. This limits rows materialized and yields between pages. A flush is additionally capped at `256 KiB` of encoded frames, and the default connection window is capped at `512 KiB / 1000 ms`; both limits are configurable and are applied before the next event is read. A single encoded frame is capped at `128 KiB`; an oversized payload is replaced by a replayable omission marker carrying the same event ID. No event retention/deletion is implemented, so there is currently no expired-old-cursor case; all valid historical cursors can replay. A cursor beyond the durable tail returns `409 RESYNC_REQUIRED`; malformed, negative, fractional and unsafe-integer cursors return 400.

Cleanup listeners are registered before the first write. If either the handshake or an event write returns false, the accepted frame is flushed via response end, the observer stops, and no further page is read. Initial backpressure creates no polling timer; later backpressure clears the existing timer. `close`, `finish`, and `error` also clear it, and flush/write guards prevent writes after end or destruction. A client resumes from its last **fully parsed** event ID; an interrupted frame must be replayed.

SSE event names permit only ASCII letters/digits plus `_ . : -`. An unsafe name becomes the protocol name `message`, while its original value remains in the JSON event. JSON serialization escapes payload CR/LF, preventing user output from forging SSE fields. Tool text and domain objects remain unchanged.

### Actual validation

`pnpm exec vitest run tests/api/server.test.ts` — exit 0, **9 tests passed**, 2026-11-18. These tests use a real Node HTTP server bound to ephemeral loopback ports and actual `fetch` streams, not a fake response object:

- Baseline API authentication, origin validation, schema rejection, idempotent/conflicting cancellation and uncommitted artifact 404.
- Exact durable cursor replay, future-cursor 409, query rejection and disconnect without cancelling execution.
- Snapshot followed by 145 events before subscription: three bounded pages arrive with exactly contiguous sequence IDs and no duplicates. Every API event query includes limit 64. Queries stop after the client disconnects.
- A 256 KiB event exceeds the real `ServerResponse` writable high-water mark during initial replay: the response ends after that intact frame; no poll timer is installed, no later writes/reads occur, and reconnecting from its sequence returns the following event.
- The same backpressure during a later polling tick clears the timer that had already been installed and stops all subsequent event queries.
- The same connection-level byte window throttles a burst without skipping or duplicating events; after the window reopens, polling continues from the last committed cursor.
- Malicious CR/LF in the event type cannot introduce a new protocol ID. Tool text with newlines, Unicode and domain fields named `token`/`authorization` is preserved. The actual API bearer header does not appear in the event. Invalid cursor strings are rejected.

The event projection deliberately differs by producer. `tool.finished` exposes attempt/execution IDs, exit code, artifact IDs and stdout/stderr byte counts; it does not expose stdout or stderr text. `tool.completed` exposes the call identity, tool name, location, success and a reduced error (`code`/`retryable`); it does not expose the returned value or error message. Validation/repair evidence, approval reasons, policy diagnostics, resource-policy details and graph details now have explicit per-event projections in `src/api/events.ts`. A real HTTP/SSE sentinel test verifies that free-form secrets in these specified fields do not reach the stream, that permitted IDs/results remain visible, and that the durable originals remain unchanged. Events not covered by a projection still pass through their producer payload; this does not establish a complete credential boundary.

The budget correlation repair is covered separately by the real local plugin regression `pnpm --dir .sources/budget test -- reservation-stream.spec.ts` (**8 tests passed**). ### Sensitive information boundary and remaining acceptance

The API does not copy Authorization headers, server configuration or credentials into events. It deliberately does **not** recursively redact keys such as `token`, or modify arbitrary tool output: those may be legitimate task evidence. Transport escaping prevents protocol injection, not disclosure of secrets deliberately emitted by a producer. A full audit of credential-bearing producer metadata, with explicit allowed fields before persistence, is still required. The above fixture does not establish comprehensive secret redaction.

#### Serial trace inspection

In `SerialWorkflow`, `workflow.role_completed` carries the workflow call ID, trusted model call ID and settlement receipt ID. The executor role and its following step are selected by the same repair-loop index, and the step ID is derived from run ID and that index. The step/attempt records carry step ID and execution ID. The emitted role completion event does not itself carry the repair index or step ID, so the complete join cannot be reconstructed from these event fields alone. The code inspection does not validate a complete trace across retries, resumed runs or other workflow entry points. Add an explicit durable association and verify replay/idempotency before claiming that join.
