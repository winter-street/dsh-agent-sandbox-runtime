## 历史实现与验证记录

### Actually exercised

Chrome 157.0.8103.52, headless, 1440 × 1100 desktop and 390 × 844 mobile. The fixture uses the actual loopback HTTP API, RuntimeService, SQLite store and ArtifactStore; its budget and sandbox adapters are controlled fakes. The UI never executes submitted code on the host.

Fourteen checks passed: create task, view snapshot, budget and soft-limit reason/mode, exact CSV download, resume, offline SSE replay, reload/re-authentication, partial delivery, verified completion, list refresh retaining selection, cancellation, one-time approval, delayed old-response isolation, mobile horizontal-overflow check. There were zero browser `pageerror` events. `localStorage` and `sessionStorage` remain empty after reload; bearer credentials travel in headers and remain in memory.

The download is checked byte-for-byte, including its filename `ranking.csv` and CSV rows (`C7,3`, `C2,1`). Partial and successful delivery have distinct labels. The controlled validator is explicit, so the successful UI state is not evidence of a real analytical task's correctness.

Selection generations and snapshot revisions prevent delayed responses from overwriting the selected task. Event chunks trigger one snapshot refresh per chunk, rather than one request for every event. The visible log retains 150 events and previews 8,000 payload characters per event; these are display bounds, not an SSE frame-byte limit. Recent durable policy decisions populate hard/soft reasons and the observe/enforce explanation.
