## Automatic executor gate (2026-11-18)

The newer `ApprovedCodeExecutor` now requests and consumes approval directly around the durable execution/retry path. It binds copied inputs, code, original run/budget/deadline, runtime configuration, retry bounds and approval configuration; persisted tool rules run before the prompt. An HTTP approval plus actual SQLite close/reopen continues the serial workflow without manually calling `consumeApproval`, repaying completed roles or redispatching code. ## Production application continuation (2026-11-18)

The production application now selects persisted serial mode through `workflow.mode=serial`. Its HTTP approval route calls `host.decideApproval`, which schedules continuation automatically and coalesces a decision arriving while the prior wait is unwinding. On reopening it schedules stored approved decisions; pending/rejected decisions remain paused. Empty Harness root/role sessions now have durable informational seeds. Approval consumption also requires positive original work availability, so observe-mode zero-cost admission cannot dispatch code after that allocation is exhausted.

The application suite now has **27 integration cases**, including approve/reject, idempotent and conflicting decisions, pending/approved close/reopen windows, expiry, configuration/input drift, depleted work budget, role-boundary pause/resume, execution cancellation, bounded retries, tool limits and unknown-state recovery. The complete local check passes **712/712 tests across 62 files, none skipped**, plus typecheck, build/client assets and frozen-fixture verification. It uses the actual Harness, original budget plugin and MCP child process with controlled provider/sandbox ports; application test reopening stays inside one Node process. Full scope is in [N04 local composition](N04-local-composition.md).
