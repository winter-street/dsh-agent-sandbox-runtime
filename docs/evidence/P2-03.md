The plugin settles four disjoint usage buckets exactly once for a reservation. Equal duplicates are no-ops; conflicting final usage fails. Only known-unsent reserved requests release capacity. Dispatched requests become unknown after interruption/reload, hold their estimate and block new model calls. Late authoritative usage can settle unknown. Actual overshoot is fully charged and later admission is denied. In-flight calls can finish settlement during plugin disposal before its writer lease is released.

`tests/reservations.spec.ts` covers these transitions, corruption, mixed replay, allocation and write failure. `tests/reservation-stream.spec.ts` covers cumulative usage replacement, missing usage even with legacy ignore, and early stream cancellation. `pnpm check` exited 0; 134 passed / 1 optional remote smoke skipped. [Raw log](logs/budget-v2-check.txt).

The service's settle method accepts a trusted supplied usage record; a remote-provider usage lookup API is not implemented. Runtime must preserve evidence for manual reconciliation, and must never infer zero usage or release a dispatch merely because a network request timed out. Crash lock cleanup is a separate explicit checked action and does not reconcile usage.
