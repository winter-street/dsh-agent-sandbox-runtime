## 可信调额续跑回归

原先预算不足进入 finalize 后，追加额度及显式 resume 会保留收尾锁定，下一步再次暂停。修复位于 `src/core/service.ts` 的 `resumeRun`。预算暂停任务经过原有 scope、账目、deadline、revision、执行状态、产物及 checkpoint 验证，并确认工作额度可用后，可信宿主显式恢复会调用既有 `PolicyEngine.releaseFinalize`。命令完成、RUNNING 转换、带操作原因的 `policy.changed` 和 checkpoint 在同一 SQLite 事务内提交。

新增场景经过原预算插件的本地 `/agent-budget/api/adjust-limit` 管理入口。缺少可信请求头的调整返回 403，合法调整追加账本事件。恢复及数据库重开后原历史、产物和期限均保留，重放恢复命令及既有步骤保持幂等，后续调用通过实际 Harness hook 结算，新的受控步骤产物成功提交。

四项核心回归覆盖零工作额度拒绝、checkpoint 写入失败的事务回滚和同命令重试，以及 PAUSED_ACCOUNTING、RECOVERY_REQUIRED 重建和恢复时保留收尾锁定。本轮采用既定设计，将可信宿主对预算暂停任务的显式恢复视为操作员解除锁定的意图。
