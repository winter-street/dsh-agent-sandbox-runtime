# Optional validated model routing

`src/models/router.ts` supplies a deterministic ModelRouter; `src/models/harness.ts` applies its selection through the actual Harness agent/request hook and validates the final llm/stream envelope before the budget hook. Switching defaults to disabled. Test profiles are explicitly marked controlled and require allowControlledProfiles. The bounded real-provider probe supplies remote profiles for deepseek-v4-pro and deepseek-flash, scoped to one fixed integer task, exact tool/output schemas and disabled thinking. The main application selects its model explicitly through configuration. Optional routing is composed through the exported createHarnessModelRouter API.

Each profile declares an exact provider/model, context window, output cap, tested task types, tool and structured-output support, validated tool/output schema hashes, reasoning efforts, evidence references and verification date. Tool-schema identities are SHA-256 of canonical JSON `{ name, parameters }`; semantic schema changes therefore need new validation. Profile metadata is an operator assertion backed by its evidence; the router cannot independently prove a provider supports the assertion.

The request includes a task type, required schema identities, output minimum/desired cap, real in-flight model count, unresolved tool count, complete-input token estimator per candidate and current budget snapshot. A candidate must fit its own input-plus-output window (including safety reserve), global capacity and work/finalize capacity. A smaller model is not assumed to tokenize like the original or to cost fewer tokens. Optional price estimates include a currency and per-million input/output rates. The fixed-task comparison records actual usage and a range based on the captured official peak/off-peak price book. Profile verification remains scoped to its recorded fixture and schema.

Selection only changes at a request boundary, with zero in-flight model calls, zero unresolved tool calls and zero outstanding reservations. A maximum-switch count and step cooldown limit later changes. Once selected, a compatible model stays selected when budget pressure falls; the router never silently switches back to a preceding profile. Incompatible current profiles either advance to a validated allowed candidate at a safe boundary or deny. Run ID, config/profile fingerprint, selected model, switch count and boundaries are persisted and checked on restore.

For Harness composition, install budget -> model-router -> model-policy. Each runtime hook uses prepend, so model-policy observes router selection on agent/request and wraps router validation on llm/stream. Both remain outside the budget stream hook. Final request validation recomputes input tokens, checks exact model/provider/output cap and validates actual tool hashes. Context expansion or altered schema after selection rejects before a reservation/provider call. Direct one-shot callers need a routing selection record or a separate explicitly defined routing path.

The adapter receives structural resolveRun/readState/commitDecision hooks. Persist routing decisions/state atomically and attach their reason/estimate to trace. Set countInputTokens from the host's full planned request and countFinalInputTokens from the actual assembled request, with provider-specific tokenization where available. It does not compress mandatory context to force a cheaper model to fit. The original budget plugin still performs one reservation and one settlement using actual usage; no model-router balance exists.

Validation includes 18 deterministic compatibility/state tests, three real Harness/original-budget tests with a controlled provider, and one bounded remote run. The remote run checks a tool and JSON response for each model, then a routed JSON request. All five calls settle once for 1256 tokens. SQLite reopen preserves the decision, with zero unknown calls or reserved tokens. Published-price estimates and correctness apply to this fixed input. General quality, calibrated tokenization and account invoice reconciliation remain later evaluation work. Commands, hashes and the preserved initial failure are in [P5-06 evidence](../evidence/P5-06.md).
